# 第4章 基因组测序数据压缩与管理系统的设计与实现（可直接用于论文）

## 4.1 系统需求分析
### 4.1.1 业务需求概述
本系统面向生物信息学实验室的 FASTQ 数据管理场景，聚焦“海量数据存储压力、命令行工具门槛高、压缩效果评估不直观”三个核心痛点，构建了一个“FastqCA 算法引擎 + Web 管理平台”的一体化系统。用户通过浏览器即可完成数据上传、参数配置、任务提交、状态监控和结果分析。

### 4.1.2 功能性需求
1. **用户管理模块**：提供注册、登录、角色区分（researcher/admin）。
2. **数据管理模块**：支持 GB 级 FASTQ 文件分片上传与合并、列表展示和状态追踪。
3. **压缩任务调度模块**：调用 FastqCA 进行无损/有损压缩，支持线程参数配置、任务排队与进度反馈。
4. **结果可视化模块**：输出 FastqCA 与 Gzip 压缩率对比图，展示质量分数分布，支持 PDF 报告导出。

### 4.1.3 非功能性需求
- **并发性**：采用 Celery + Redis 异步任务架构，避免大文件压缩阻塞 Web 请求线程。
- **响应性**：前端使用 Vue + Element Plus 实现响应式界面，支持实验室常见显示终端。

## 4.2 系统总体设计
### 4.2.1 系统技术架构设计（B/S）
系统采用四层架构：
- 表现层：Vue.js + Axios + ECharts；
- 业务逻辑层：Flask API + FastqCA Wrapper；
- 数据处理层：Celery/Redis + 文件存储；
- 数据持久层：MySQL/SQLite（开发阶段）。

### 4.2.3 数据库设计
核心数据表：

## 4.3 系统详细实现
### 4.3.1 开发环境与配置
- OS：Windows 10 / Ubuntu 20.04
- 工具：PyCharm、VS Code
- 后端：Python 3.8+，Flask，Celery，Redis
- 前端：Vue 3，Element Plus，ECharts

### 4.3.2 核心算法引擎集成实现
系统通过 `subprocess` 调用现有 `main_new.py`，将压缩逻辑无缝复用到 Web 服务中。任务创建后，由 Celery Worker 在后台执行 FastqCA 与 Gzip 对照压缩，并更新任务进度与状态。

异步流程：
1. 用户提交压缩请求；
2. Flask 返回 `task_id/task_uuid`；
3. Celery 异步执行压缩；
4. 前端轮询 `/api/tasks/{id}` 更新进度条；
5. 完成后下载结果与 PDF 报告。

### 4.3.3 数据可视化模块实现
采用 ECharts 实现压缩对比柱状图，展示 Original/FastqCA/Gzip 三组数据。质量分数分布数据由 Biopython 读取 FASTQ 后统计，生成曲线或柱状图，用于展示有损模式对关键质量信息的保留能力。
