# 第4章 基因组测序数据压缩与管理系统的设计与实现（修订稿）

## 4.1 系统需求分析
### 4.1.1 业务需求概述
本系统面向生物信息学实验室的 FASTQ 数据管理与压缩场景，围绕“数据规模大、命令行使用门槛高、实验记录难管理”三类问题，构建了“FastqCA 算法引擎 + Web 管理平台”的一体化系统。用户通过浏览器即可完成登录、任务提交、压缩历史追踪、性能监测与用户管理。

### 4.1.2 功能性需求（四模块）
系统前端以左侧菜单组织为四个核心模块：
1. **压缩任务模块**：上传 FASTQ 文件，配置无损/有损（Q4）模式与线程数，提交压缩任务并查看进度。
2. **压缩历史模块**：查看历史任务记录（输入/输出大小、压缩比、耗时、速度、完成时间）。
3. **性能监测模块**：展示 CPU/内存趋势、任务总量、平均压缩速度、最大内存峰值等运行指标。
4. **用户管理模块**：展示用户列表、角色信息（researcher/admin）与角色维护能力。

### 4.1.3 非功能性需求
- **并发性**：采用异步任务机制，避免大文件压缩阻塞 Web 请求。
- **可用性**：前端提供离线演示数据回退模式，后端不可用时仍可演示完整页面流程。
- **可视化友好性**：使用 ECharts 图表展示压缩效果与性能趋势，支持论文截图与答辩展示。

## 4.2 系统总体设计
### 4.2.1 系统技术架构设计（B/S）
系统采用 B/S 架构，分为四层：
- 表现层：Vue 3 + Element Plus + ECharts；
- 业务层：Flask API + FastqCA 封装接口；
- 任务层：异步任务队列（可扩展 Celery/Redis）；
- 数据层：用户、文件与任务元数据持久化。

### 4.2.3 数据库设计
可采用 3 张核心表：
- `users`：用户名、密码哈希、角色、创建时间；
- `files`：文件名、路径、输入大小、输出大小、所属用户；
- `tasks`：任务模式、线程数、状态、进度、压缩比、耗时、报告路径。

## 4.3 系统详细实现
### 4.3.1 开发环境与配置
- OS：Ubuntu 20.04 / Windows 10
- 后端：Python 3.8+，Flask
- 前端：Vue 3，Element Plus，ECharts
- 开发工具：PyCharm、VS Code

### 4.3.2 压缩任务与历史实现
系统通过 Python 封装 FastqCA 主程序，前端提交任务后由后端异步执行压缩。执行完成后将结果写入任务记录，压缩历史模块从任务表聚合展示完整实验轨迹。

流程如下：
1. 用户登录后上传 FASTQ 并设置压缩参数；
2. 系统创建任务并返回任务 ID；
3. 后台执行 FastqCA 压缩并更新进度；
4. 前端展示任务状态与历史记录；
5. 用户下载压缩结果与报告。

### 4.3.3 性能监测与用户管理实现
- **性能监测页面**：统计任务总数、平均压缩速度、CPU 平均占用、最大内存峰值，并绘制 CPU/内存时间序列折线图。
- **用户管理页面**：展示用户账号、角色、所属课题组与创建时间；管理员可进行角色调整。
